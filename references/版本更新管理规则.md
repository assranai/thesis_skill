# 版本更新管理规则

## 1. 总则

### 1.1 目的

规范毕业设计论文的版本管理流程，确保每次变更可追溯、可回滚、可审计。

### 1.2 适用范围

本规则适用于本项目目录下的所有文件，包括：
- LaTeX源文件（`*.tex`）
- 模板类文件（`*.cls`）
- 参考文献文件（`*.tex`, `*.bib`）
- 图片文件（`figure/*.png`, `*.jpg`, `*.pdf`）
- 配置文件（`*.sty`, `*.bst`）
- 流程文档（`*.md`）
- Kimi调研产出（`kimi调研/*`）

## 2. 版本号规则

由于本项目的文件类型多样，采用 **内容层版本号 + 文件层时间戳** 的双层体系。

### 2.1 论文内容版本号

格式：`v<主版本>.<次版本>.<修订号>`

| 级别 | 说明 | 示例 |
|------|------|------|
| **主版本** | 里程碑级变更，如开题→中期→初稿→终稿 | v1, v2, v3 |
| **次版本** | 章节级变更，新增/重写章节 | v1.1, v1.2 |
| **修订号** | 局部修改，格式修正，bug修复 | v1.1.1, v1.1.2 |

版本号演化示例：

```
v1.0.0   开题报告完成
v1.1.0   中期报告完成（新增第4章）
v1.1.1   中期报告图片修正
v1.2.0   新增第5章（后期计划）
v2.0.0   论文初稿完成
v2.1.0   根据导师意见修改第3章
v2.1.1   修复编译警告
v3.0.0   终稿提交
```

### 2.2 文件更新时间戳

每个文件的最后修改时间作为文件级版本标识。

关键文件的版本号记录在文件头部的注释中：

```latex
% !Mode:: "TeX:UTF-8"
% !Version:: v1.2.0
% !LastMod:: 2026-05-06
% !Status:: draft/review/final
```

### 2.3 版本号与编译输出的对应

每次成功编译生成的PDF，文件名格式：

```
report_v<主版本>.<次版本>.<修订号>_<日期>.pdf
```

示例：`report_v2.1.0_2026-05-06.pdf`

## 3. 变更管理流程

### 3.1 变更类型

| 类型 | 代码 | 说明 | 示例 |
|------|------|------|------|
| 新增内容 | `[ADD]` | 新章节/段落/数据 | 新增4.3节 |
| 修改内容 | `[MOD]` | 修改已有内容 | 重写摘要 |
| 修复问题 | `[FIX]` | 修复错误/编译问题 | 修正引用格式 |
| 格式微调 | `[STYLE]` | 排版/格式调整 | 调整表格样式 |
| 删除内容 | `[DEL]` | 移除内容 | 删除冗余段落 |

### 3.2 变更记录文件

每次变更必须在 `版本更新记录.md` 中记录。文件位于项目根目录。

### 3.3 变更操作流程

```
[发起变更] → [执行变更] → [编译验证] → [记录版本] → [通知导师]
     ↓            ↓             ↓             ↓             ↓
  明确范围    修改文件     xelatex编译   更新CHANGELOG  导师审阅
```

**详细步骤：**

1. **发起变更**：明确变更类型、涉及文件、预期结果
2. **执行变更**：Agent按规范修改文件
3. **编译验证**：
   - 运行 `xelatex report.tex`（至少两次确保交叉引用）
   - 检查 `report.log` 中的 error/warning
   - 无 error 方可提交
4. **记录版本**：更新 `版本更新记录.md`
5. **通知导师**：提交变更摘要

## 4. 版本更新记录（CHANGELOG）

### 4.1 格式规范

`版本更新记录.md` 使用以下格式：

```markdown
# 版本更新记录

## v3.0.0 (2026-06-xx)
### [ADD]
- 新增致谢章节
### [MOD]
- 根据导师意见修订全文
### [FIX]
- 修复所有编译警告

## v2.1.0 (2026-05-06)
### [MOD]
- 根据导师意见修改第3章研究方法描述
- 更新Kriging公式推导
### [FIX]
- 修正图片索引偏移问题（image1/image2为校徽校名，已弃用）
- 修复任务书页换行溢出（ulinel改用parbox）
- 全部引用改为上标格式（\upcite）

## v2.0.0 (2026-05-06)
### [ADD]
- 初稿完成，整合开题+中期报告
- 新增第1章 选题依据
- 新增第2章 研究目标与内容
- 新增第3章 研究方案
- 新增第4章 现阶段研究进展
- 新增第5章 后期工作计划
### [STYLE]
- 采用buaathesis模板格式
- 32篇参考文献统一排版
- 13张图片从Word文档导出并命名

## v1.1.0 (2026-04-xx)
### [ADD]
- 中期报告完成
- 新增第4章 研究进展

## v1.0.0 (2026-02-xx)
### [ADD]
- 开题报告完成
```

### 4.2 维护规则

- 每次变更后立即更新，**不允许批量累积**
- 按时间倒序排列（最新的在最上面）
- 每项变更用 `[类型]` 前缀分类
- 关联对应的Kimi调研文件（如有）

## 5. 文件完整性校验

### 5.1 关键依赖检查

编译前由Agent检查的关键依赖：

```
□ buaathesis.cls           — 模板类文件
□ figure/*.png             — 所有引用图片存在
□ font/SimSun.ttc          — 中文字体
□ font/TimesNewRoman.ttf   — 英文字体
□ data/*.tex               — 所有章节文件存在
□ data/references.tex      — 参考文献文件
```

### 5.2 命名一致性

同一次版本迭代中，文件命名变更需保持一致：

- 图片重命名 → 同步更新所有 `\includegraphics` 引用
- 章节文件重命名 → 同步更新 `report.tex` 中的 `\include`
- LaTeX标签（`\label`）重命名 → 同步更新所有 `\ref`/`\upcite`

## 6. 回滚策略

### 6.1 回滚触发条件

- 编译产生无法修复的error
- 导师要求撤销某次变更
- 整合内容后发现与前期内容冲突

### 6.2 回滚操作

```
回滚方式1: 文件级回滚
从版本更新记录中找到上版本状态
恢复对应文件的上版本内容
→ 编译验证 → 记录回滚

回滚方式2: 整版回滚
从编译输出目录中找到上一版PDF
用上版源文件替换当前源文件
→ 编译验证 → 记录回滚
```

### 6.3 回滚记录格式

```markdown
## 回滚记录
- 回滚版本: v2.1.0 → v2.0.0
- 回滚原因: [具体原因]
- 回滚范围: [涉及文件列表]
- 操作时间: 2026-05-06 15:30
- 操作用户: Agent
```
