# 毕设工作流程规则

## 1. 总览

本毕业设计采用"双轨协作"模式：

```
┌─────────────────────────────────────────────────┐
│                 双轨协作模式                       │
│                                                   │
│   Track A (Kimi端)         Track B (Agent端)       │
│   ┌─────────────────┐    ┌─────────────────┐      │
│   │  研究问题单项求解 │    │  论文整合与管理   │      │
│   │  · 文献调研       │    │  · LaTeX排版     │      │
│   │  · 方法探索       │    │  · 章节整合      │      │
│   │  · 数据/图表生成  │    │  · 版本管理      │      │
│   │  · 公式推导       │    │  · 格式规范校验  │      │
│   └────────┬────────┘    └────────┬────────┘      │
│            │                      │               │
│            └────── 监管者(导师) ──┘               │
│                     审阅/反馈                      │
└─────────────────────────────────────────────────┘
```

### 1.1 角色定义

| 角色 | 职责 | 工具 |
|------|------|------|
| **监管者（导师）** | 顶层方向把控、里程碑审核、最终内容确认 | 审阅反馈 |
| **Kimi（网页AI）** | 单项研究问题的深度探索、文献调研、方法论证 | kimi.ai（网页端） |
| **Agent（Sisyphus）** | 论文整合编排、格式规范、版本管理、质检 | LaTeX引擎、Git |

### 1.2 核心原则

1. **内容为王，格式为辅**：Kimi负责研究内容（做什么、为什么、怎么做），Agent负责格式规范（排版、引用、一致性）
2. **监管者最终裁决**：任何分歧以导师意见为准
3. **每次只改一个维度**：Kimi输出原始内容 → Agent整理格式 → 导师确认内容 → Agent终版
4. **可追溯**：所有变更通过版本管理记录

## 2. Track A：Kimi 端工作流程（研究问题单项求解）

### 2.1 触发条件

以下场景使用Kimi端处理：

- 文献检索与综述撰写
- 研究方法的可行性论证
- 公式推导与理论分析
- 数据/图表生成
- 算法思路探索
- 创新点论证

### 2.2 输出的标准规范

Kimi每次输出应包含以下元信息头部：

```
---
任务: [本次解决的研究问题]
输入上下文: [依赖的前置研究/数据]
输出格式: [Markdown/图表/数据表]
相关文件: [涉及的项目文件路径]
时间戳: [YYYY-MM-DD HH:MM]
---
```

### 2.3 输出要求

1. 使用Markdown格式，方便Agent端进一步加工
2. 图表尽量以数据驱动格式输出（如表格数据+Python绘图代码）
3. 公式使用LaTeX语法（`$...$` 或 `$$...$$`）
4. 参考文献注明来源（便于Agent端统一管理）

### 2.4 命名规范

Kimi产出的文件放入 `kimi调研/` 目录下，命名规范：

```
kimi调研/
├── 2026-05-06_问题简述.md        # 单次输出的对话摘要
├── 2026-05-06_问题简述_附图.png   # 关联的图表
├── data/                          # 导出的数据文件
└── README.md                      # 目录索引
```

## 3. Track B：Agent 端工作流程（论文整合与管理）

### 3.1 触发条件

以下场景使用Agent端处理：

- 将Kimi输出的内容整合到LaTeX论文中
- 章节结构调整与编排
- 参考文献格式统一
- 格式规范自动校验（字体、行距、页边距等）
- 编译检查与错误修复
- 版本管理操作

### 3.2 输入-处理-输出（IPO）规范

```
输入:  Kimi产出的研究内容（Markdown/数据）
      + 导师审阅意见
      + LASiTEX模板（buaathesis.cls）
处理:  内容整合 → 格式规范 → 编译校验 → 版本记录
输出:  report.tex + 配套数据文件
```

### 3.3 Agent处理规范

Agent在每次操作时必须遵守：

**Step 1 - 前置检查**
- 确认输入内容来自Kimi或导师
- 确认输出的目标章节位置
- 确认格式规范（字体、字号、行距）

**Step 2 - 格式规范映射**
- Kimi的Markdown → LaTeX格式转换规则：
  - `# 标题` → `\chapter{标题}`
  - `## 标题` → `\section{标题}`
  - `### 标题` → `\subsection{标题}`
  - `**加粗**` → `\textbf{加粗}`
  - 列表 → `itemize/enumerate` 环境
  - 表格 → `table/tabular` 环境
  - 图片 → `figure` 环境

**Step 3 - 编译校验**
- 每次更新后运行 xelatex 编译
- 检查日志中的 error/warning
- 修复所有编译错误
- 确认PDF输出正常

**Step 4 - 版本提交**
- 编译通过后提交版本
- 提交信息格式：
  ```
  [章节/模块] 变更内容简述
  
  - 变更类型: 新增/修改/修复
  - 关联Kimi输出: [文件名]
  - 导师确认: 是/否
  ```

### 3.4 论文文件结构


## 4. 监管者（导师）介入点

导师在以下节点必须参与：

### 4.1 节点一：研究方案确认
- Kimi产出研究方案 → Agent整理格式 → **导师确认方案可行性** → Agent推进

### 4.2 节点二：阶段性成果审核
- 每完成一个章节 → Agent通知导师 → **导师审阅内容** → 意见反馈至Kimi/Agent

### 4.3 节点三：终版确认
- 全部章节完成 → Agent格式终检 → **导师确认终版** → Agent提交最终版本

### 4.4 导师反馈处理规范

导师反馈以以下形式之一给出：

1. **直接批注**：在PDF/Word上标注 → Agent逐条处理
2. **文字意见**：通过消息给出 → Agent录入TODO → 分配给Kimi或自行处理

Agent处理导师反馈的流程：

```
收到反馈 → 分类 → 内容问题→交Kimi处理
                 → 格式问题→Agent自行修复
                 → 结构问题→提出方案→导师确认→执行
```

## 5. 迭代周期

### 5.1 单次迭代周期

```
Day 1: 导师下达任务 → Kimi启动研究（Output: Markdown）
Day 2: Agent整合内容至LaTeX（Output: draft PDF）
Day 3: 导师审阅（Output: 反馈意见）
Day 4: Kimi/Agent 修改（Output: revised PDF）
Day 5: 导师确认/再次反馈
```

### 5.2 里程碑节点

| 里程碑 | 内容 | 预计时间 |
|--------|------|---------|
| M1 | 开题报告（已完成） | 2026年2月 |
| M2 | 中期报告（已完成） | 2026年4月 |
| M3 | 初稿完成 | 2026年5月 |
| M4 | 导师审阅修改 | 2026年5-6月 |
| M5 | 终稿提交 | 2026年6月 |
| M6 | 答辩 | 2026年6月 |

## 6. 质量检查清单

### 每次Agent提交前检查项

- [ ] LaTeX编译无error
- [ ] 目录页码正确
- [ ] 所有交叉引用（\ref/\upcite）有效
- [ ] 图片正确显示、图题匹配
- [ ] 表格格式正确
- [ ] 参考文献格式统一
- [ ] 页眉页脚符合模板要求
- [ ] 字体、字号符合规范
- [ ] 导师上次反馈已全部处理

## 7. 通讯协议

### 7.1 Kimi → Agent 交接格式

Kimi产出的研究内容，需在文件头注明：

```markdown
---
task: 描述本次解决的问题
input_ref: 依赖的前置文件/数据
output_target: 要整合到的LaTeX文件路径
figures: 关联的图表文件列表
refs: 新增的参考文献
status: draft/review/final
---
```

### 7.2 Agent → 导师 提交格式

Agent完成整合后，需输出变更摘要：

```markdown
## 变更摘要
- 涉及文件: chapterX-xxx.tex, figure/xxx.png
- 变更类型: 新增内容 / 修改内容 / 修复问题
- 引用新增: [ref1, ref2, ...]
- 待导师确认: [需要确认的具体问题]
```
